# Codegen

## Overview

Codegen's function is to parse the ImplGraph generated by Schedule, generate actual executable code, including code running on the Host side (Host Code) and Device side (Kernel Code), where:

- **Host Code**: Code executed on the Host side, includes the following contents:
  - **tiling_func**: Responsible for dividing computation tasks into smaller blocks (tiling) for efficient execution on Device.
  - **infer_shape**: Infer the shape of each tensor to ensure the correctness of subsequent calculations.
  - **get_kernel**: Obtain and generate kernel code on the Device side.
- **Kernel Code**: Kernel code executed on the Device side, includes the following contents:
  - **kernel**: Specific computation logic.
  - **tiling_data**: Structure used to describe how to divide and process data.

The input of Codegen is the ImplGraph generated by Schedule, which contains basic elements for code generation such as shape information, node information, and axis information. An example of ImplGraph is as follows:

The specific information on the graph is as follows:

```text
// size describes the computation size
Sizes:
  z0z1t_size: VAR
  z0z1Tb_size: VAR

// axis describes axis information, including size, type, alignment, etc.
Axis:
  z0(0) : 200, ORIGINAL, align: -1, allow_oversize_axis: 0, allow_unaligned_tail: 1
  z1(1) : 200, ORIGINAL, align: -1, allow_oversize_axis: 0, allow_unaligned_tail: 1
  z0z1(2) : 40000, ORIGINAL, align: -1, allow_oversize_axis: 0, allow_unaligned_tail: 1  // ORIGINAL represents the original unsplit axis
  z0z1T(3) : Ceiling((40000 / (z0z1t_size))), TILE_OUT, from: {z0z1, }, align: 1, allow_oversize_axis: 0, allow_unaligned_tail: 1
  z0z1t(4) : z0z1t_size, TILE_IN, from: {z0z1, }, align: 1, allow_oversize_axis: 0, allow_unaligned_tail: 1  // TILE_IN represents the inner axis split by UB
  z0z1TB(5) : Ceiling((Ceiling((40000 / (z0z1t_size))) / (z0z1Tb_size))), BLOCK_OUT, from: {z0z1T, }, align: 1, allow_oversize_axis: 0, allow_unaligned_tail: 1
  z0z1Tb(6) : z0z1Tb_size, BLOCK_IN, from: {z0z1T, }, align: 1, allow_oversize_axis: 0, allow_unaligned_tail: 1  // BLOCK_IN represents the inner axis split between cores

// node, each node will generate an api call in the kernel code
Nodes:
......
  abs_test/gather_0: Load (1)
......
  abs_test/abs_0: Abs (2)
    .axis = {z0z1TB, z0z1Tb, z0z1t, }
    .loop_axis = z0z1Tb
    .api:
      .compute_type = elewise
      .type = Compute
      .unit = Vector
    .x = abs_test/gather_0.y
    .y.dtype = float32
```

## Output Content

### Device-side Code (Kernel)

The Device-side code is the core fusion kernel code written in AscendC, including the complete calculation logic of all fused operators. It will eventually be compiled into a Device binary by the BiSheng compiler and executed on the Ascend NPU.

### Host-side Code

- **Tiling Function**: Calculate the tiling parameters according to the actual input shape at runtime, and pass the parameters to the Device kernel.
- **Infer Shape**: Calculate the output shape according to the input shape for dynamic shape scenarios, ensuring the correctness of the subsequent calculation process.
- **Tiling Data**: Fixed tiling parameter data and structure definitions, shared by multiple runs.

Workspace sizes and byte offsets use `uint64_t`, so a single workspace larger than 2 GiB and an accumulated size larger than 4 GiB are not truncated. The direct tiling ABI uses `uint64_t *workspace_size`; host-side accumulation and 512-byte alignment use checked calculations and return failure on overflow. Non-Inductor direct tiling retains the existing 16 MiB reserved-workspace semantics after workspace accumulation.

## Main Workflow

1. **Parse Scheduled Result**: Read the fused graph structure, tiling grouping, memory planning and other information from the scheduling result.
2. **Generate Device Kernel**: Assemble the AscendC code according to the node sequence and calculation logic, implement the complete calculation process.
3. **Generate Host Code**: Generate the Tiling function code and InferShape code according to the calculation and shape information.
4. **Output Source Code**: Output the complete Host and Device source code files for subsequent compilation by BiSheng.
