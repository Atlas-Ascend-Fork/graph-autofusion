# step 2 原计划 4 格，实际交付 2 格：2b 已退回，原因记下来
#
#   `round_to_int` / `trunc_to_int` 写过一遍、UT 也过了，但**实测让它们从干净回落变成
#   硬失败**（takeover 79 -> 81 而 hard-failure 11 -> 13），所以整个 2b 退回。
#
#   卡点**不是**那张 (输入, 输出) 对表——对表量清楚了，而且结论有用：那 8 对全在
#   `getRegBasedCastPairs()` 里，但 reg 的 cast 表还多 `f32->i8` 与 `f16->i64`，所以不能
#   复用 `CastPair`（会比 legacy 宽，宽就是注册表里的一句假话），要另起一张 8 对表。
#
#   真卡点是 **`afir.store` 的「两端 dtype 必须相同」**。legacy 自己调度出来的图就是矛盾的：
#
#     func @round_to_int_float_to_int32_test_0_B0Y2_S0G0C0(%data: f32[s0,s1], %output: f32[s0,s1])
#       %2 = ascir.ops.RoundToInt(%1) -> vector<z0z1t_sizexi32>
#       %3 = ascir.ops.Store(%2) -> output: %output        <- %output 是 f32
#
#   存的是 i32、GM 那一侧是 f32。那个 f32 是 legacy 在 MLIR 跑起来之前定的（函数签名出自
#   legacy 的调度结果）。legacy 的 store 按字节搬、两者都是 4 字节所以它「能跑」；MLIR 的
#   `afir.store` 有那条不变量，于是硬失败。**与 uint8 那一族是同一道闸门。**
#
#   不为这两格放开 store 那条闸门：硬失败换成按字节重解释的静默错值更糟，而且影响所有图。
#   接 2b 的前置是先给「两端 dtype 不同但字节宽度相同」的 store 定语义（capability 层干净
#   拒收，或显式建模成一次 reinterpret），那是独立一件活。
#
