# 简介

## 目的

归档 v35 ATT 现有 `GetOpHeadCost` 系数的测量边界和复算方法。

## 范围

适用于引用该公共项的 v35 候选。VF、MTE2、MTE3 等单 API 的 head 成本仍按各自公式处理。

# 总体概述

## 软件概述

本实验用两个独立的 AscendC bench 测量任务时间和 AIV PMU cycles。原实验使用 Ascend 950 / CANN 9.3.0。

## 软件功能

工具核对 launch 与 profiling，按组提取中位数，再拟合核数斜率和计算留出误差。

## 设计约束

训练、留出和对照预先划分。采集的核数是实验取点，生产仍使用候选算出的核数。

## 假设和依赖关系

采集需要匹配设备的 CANN、msprof，以及至少 50 个可用 AIV 核；复算依赖 Python 3.9+。

# 需求分析与设计

## 整体介绍

`PerfParamTableV2::GetOpHeadCost` 返回每个活跃核的公共成本，现有目标函数在 pipe 成本外加入
`22.059531283 × 建模核数`。先建立任务时间与 PMU 的量纲换算，再用独立的空 kernel 拟合核数斜率。

## 功能需求

| 实验 | 训练点 | 留出和对照 | 处理 |
| --- | --- | --- | --- |
| 标量循环换算 | 3、24、48 核；循环 128、512、2048 次 | 256、1024 次留出；0 次为对照 | 按轮次和核数，分别拟合 task μs 和 AIV PMU cycles/核随循环次数变化的斜率，两者之比取中位数 |
| 空 kernel 核数斜率 | 3、6、12、24、36、48 核 | 5、15、18、30、42、50 核留出；每核写一个标记的 kernel 仅作对照 | 将 task μs 乘以换算系数，按核数做含截距的普通最小二乘拟合 |

## 非功能需求

采样计划固定在 [用例清单](cases.csv)；[工具说明](../../../../tools/modeling/op_head_cost/README.md)
给出设备采集和离线复算命令。测量文件、运行结果和工具分目录保存。输出有误、计数不匹配、样本缺失或拟合无效时终止。

## 性能

本次归档和注释不改变产品编译、tiling 或 kernel 执行性能，也不增加交付包或常驻内存。
单次空任务标定不能证明所有 v35 候选排序都会改善。

## 接口设计

`collect.sh <build-dir> <new-run-dir>` 将采集结果写入指定的新目录，
`calibrate.py fit <samples.csv>` 将拟合结果输出至标准输出。输入无效返回非零；
只改动仓内实验入口，无产品 API/ABI 变化。

## 软件设计

数据流为 `msprof + launch 回执 → 分组中位数 CSV → 独立换算 → 空任务斜率与留出误差`。
两组各运行四轮，顺序为正、反、反、正；每组预热 3 次，再取 31 个正式样本的中位数。
核对 kernel 名、核数、顺序、单 stream 和输出／保护区校验回执。回归使用 `Task Duration(us)`；
ACL event 仅用于诊断。AIV PMU 周期按试验口径除以 block 数。候选、默认与 PGO 实测不参与拟合。

每条 CSV 记录保存 bench、轮次、核数、工作量、训练角色、样本数和两种计量值。
实验截距只用于评估拟合误差；产品沿用既有常量归属，仅使用斜率。PMU 和 task 减 PMU 的斜率分别报告，
用于说明两种计量口径的差异，不能归因到某一条退出指令。采集或审计失败后保留本轮现场，换新目录重试。

## 安全检查

两个独立 bench 使用固定大小的缓冲区，等任务完成后校验和释放。工具不覆盖已有输出目录。
完整 profiling 不提交；归档仅保留分组结果和来源摘要。

## 兼容性检查

离线复算不需要 NPU。重新采集需要支持所列核数和计数器的 v35 设备。V1 不使用该系数。

## 测试设计

运行工具说明中的离线复算命令，并与[冻结实测结果](results/v35/pr2921-d68/report.md)核对。
`UTestAscirPerfV2.TestGetOpHeadCostValid` 覆盖产品常量读取；默认与 PGO 的排序、精度和性能需用真实候选另验。

## 验收标准

由训练组复算出已归档的系数和留出误差，且独立保留对照组。空任务结果不作为产品回归结论。
