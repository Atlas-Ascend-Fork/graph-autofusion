# 简介

## 目的

记录 v35 Load、Store、NDDMA、Transpose 和 VF 的估值增补，提供可复查的描述符条件、系数和采集用例。

## 范围

涉及 Autofuse 的 ATT 性能表达式与默认 tiling 排序。本目录记录各模型的独立数据及适用范围。

# 总体概述

## 软件概述

### 项目介绍

ATT 根据 Codegen 的物理搬运和指令描述计算各流水成本，并使用模型目标函数比较合法的 tiling。

### 产品环境介绍

标定来自 Ascend 950/v35 的既有采集器与 CANN Toolkit。硬件条件用现有 v35 模型注册和平台参数表达。

## 软件功能

在实测覆盖的描述符上应用相应标定。符号条件随 tiling 实例化求值，域外保留原表达式。

## 设计约束

分开记录 PMU cycle、task cycle 和设备墙钟。训练、留出、已知候选和域外对照独立标记。仓内保存用例、逐点结果及外部证据索引。

## 假设和依赖关系

以生成代码的 API、地址推进、同步节奏和缓存策略为标定前提。跨缓存策略与其他平台的数据分别验证。

# 需求分析与设计

## 整体介绍

Codegen 描述符进入 ATT 模型工厂。工厂生成估值及必要的 guard，Host tiling 使用真实 shape、tile 和活跃核数求值。

## 功能需求

### 搬运估值

输入包括 dtype、物理轴、GM/UB stride、有效字节数和活跃核数。Load/Store 复用带宽模型，NDDMA 根据归一化后的描述符选择带宽或残差分支。输出为 MTE2/MTE3 cycle 表达式。

### 向量估值和公共成本

Transpose 用实际 Gather bank 周期和掩码 lane 数计算 VEC 成本。VF 依据指令依赖和发射代价建模，公共启动斜率进入 v35 目标函数。

## 非功能需求

### 可维护性

描述符条件与公式保存在各模型目录。系数可追溯至各实验的冻结版本。

### 可测试性

用例清单可通过对应的采集入口重放。UT 验证产品估值、动态 guard 和域外回退。

### 可移植性

v35 注册表承载本次估值。位宽、对齐和核数按模型及平台配置读取。

### 可靠性

既有 descriptor 校验在建模前执行。无法证明命中适用域时保留原公式。

### 特性交叉影响

| 场景 | 结论 |
| --- | --- |
| SuperKernel Python、C++ 和 AOT | 不涉及，其产物与估值注册分离 |
| Autofuse 图优化 | 本归档覆盖估值，图优化 pass 的修订另有功能测试 |
| Autofuse Codegen/Backend | Host 估值及默认选解可能变化，需检查实际发射的 tiling |
| AscendC API、Runtime、Python/C++ 绑定 | 沿用现有设备描述符与外部入口 |
| 构建和打包 | 使用原构建与交付入口 |
| 测试和覆盖 | 模型 UT、描述符实验及 PGO 关闭的设备回归 |
| 性能和日志 | 关注 Host 表达式、冷编译和设备耗时，建模分支信息在 debug 日志输出 |
| 兼容性 | 原模型域外回退与 V1 平台的既有规则均应保留 |

## 性能

### 编译时长

符号域检查增加估值表达式。Host 冷求解、缓存命中和冷编译分别与 Base 对照。默认搜索的重复求解与模型拟合误差分别计量。

### 执行性能

新估值可能改变 tiling。必须关闭 PGO，核对真实发射、精度和设备耗时。组件 cycle 只用于验证对应模型。

### 内存和产物大小

新增数据为轻量 CSV、报告和证据索引。原始 profile、plog、二进制与大张量存放在实验环境。

## 接口设计

### 新增/修改接口描述

沿用模型工厂与 tiling 表达式接口。估值输入来自既有 dtype、shape、stride 和核数字段。NDDMA 的 debug 模型名可以表示有条件的表达式。

### 接口检查项

| 检查项 | 说明 |
| --- | --- |
| 对外接口、ABI | 模型归档不新增公开入口 |
| 参数域和错误 | 超出拟合域使用原式，非法描述符沿用原错误处理 |
| 接口测试 | 模型工厂 UT 覆盖静态和符号条件 |

## 软件设计

### 关键数据结构

既有 DMA 描述符及 `PerfOutputInfo` 保存估值和条件表达式。归档以 case ID 对齐 `cases.csv` 和 `samples.csv`。

### 关键技术/算法

复用现有模型形式。新参数由匹配的独立采集得到。用原始 descriptor 区分连续、跨 pitch、LoopMode、NG2 和稀疏多轴。

### 流程设计

核对实际 API 和计量条件，冻结拟合数据，核对独立留出，生成产品估值，验证候选排序，关闭 PGO 验证默认并回归。

### 错误处理

#### 系统错误

采集、精度、profile 或证据摘要不齐的结果保留原状态，按原实验协议诊断和复测。

#### 接口错误

非法 descriptor 沿用原模型入口的回退或错误码。符号模型的 debug 日志显式记录可能的路径。

## 安全检查

沿用原 shape/stride 校验、符号长度计算、图执行及资源生命周期。新增估值不接入设备 API。归档包含描述符和摘要。

## 兼容性检查

用例索引与旧 Transpose 归档并列。原报告和旧采集保持可读。v35 之外沿用已有调度配置。

## 测试设计

### 测试边界

分别验证固定描述符、动态条件和设备默认解。冷读或地址复用对照保留各自缓存口径。

### 测试用例设计

| 类别 | 覆盖 |
| --- | --- |
| UT | 适用域边界、其他 dtype、符号 guard、模型回退 |
| 采集 | 独立训练、独立留出、已知候选、域外对照 |
| 设备回归 | PGO 关闭的实际发射、精度、业务门禁和逐例回退 |
| 工程性能 | 无缓存 Host 求解、缓存命中、冷编译分别验收 |

### 测试命令

使用 `sh build.sh -u --module=autofuse_framework -j 8` 构建验证。各模型的设计页列出定向 UT，采集入口见对应结果 manifest。

## 验收标准

逐条核对 descriptor 与采集口径，验证拟合误差和候选排序。产品默认需满足精度、性能、回归和 Host 工程门禁。归档的历史组件数据按各自运行口径解读。
