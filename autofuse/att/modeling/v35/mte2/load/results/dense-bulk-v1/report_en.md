# FP32 dense narrow-row Load calibration

Business-candidate records, full tiling, Host timings and 17/48-case regression evidence are tracked at a pinned revision in [CANN-DevTools](https://gitcode.com/zhang_shengjie/CANN-DevTools/blob/6733c737b04f2e6289ebeb5784adaccb7c1e6d30/att_generalization/report/20261119/pr3065-model-regression/README.md). This directory retains API modeling rationale, independent training/holdout data and validation summaries.

The existing `h + payload_bytes/(a + b/active_cores)` form is retained. The new domain is FP32, exactly two dimensions after removing static unit axes, 512–2048 rows, 8–32 elements per row aligned to 32 bytes, zero GM/UB gaps, 16–64 KiB, and 16–56 active cores. Hardware LoopMode, single-row, strided and other-dtype inputs retain their existing models. This is a measured active-core domain, not a device-core-count special case.

Only seven training points fit h=142.17870407217006, a=1.1266553015411542, b=1126.6553015411544. Maximum error is 9.20% on training, 11.24% on five holdouts, 12.39% on the unused known candidate, and 8.12% on three additional points collected after freezing the coefficients. See [cases](cases.csv), [samples](samples.csv), [fit](fit.json), and [plot](fit.svg).

The existing DMA collector executes K=1/2/4/10 calls with 16 warmup and 16 measured samples per K, a 4 GiB fresh-offset pool and disabled-L2 hint. Queue, synchronization, tail-store consumption and guard checks are shared by ordinary Load, hardware LoopMode and NDDMA. Every descriptor passed precision and guard verification. Fit the slope of per-core MTE2 cycles against K. [Control samples](api-control-samples.csv) preserve the K medians; NORMAL-hint NDDMA controls remain separate. At 56 active cores and `[2048,8]`, ordinary Load measured 3683.19 cycles, LoopMode 18839.87, disabled-L2 NDDMA 4515.75 and NORMAL NDDMA 4812.14. NDDMA coefficients are unchanged.

Reproduction commands, exact API inputs and limitations are in the [Chinese report](report.md#采集和复现). Use the existing `dma/collect.sh loop` binary with the three archived factor CSVs, then `summarize_nddma.py --samples-per-k 16`. Offline refit uses `mte2/calibrate.py cases.csv samples.csv --fit LoadAlignedDenseBulkPayload --policy C_fresh_disable`. Only training rows participate.

On the 56-AIV device, standalone materialized transpose defaults to result0/g0/case0: 200.435 μs versus frozen Top10 PGO replay 200.280 μs. Transpose + Softmax defaults to result0 with actual device cases 1/1/4: 444.757 μs versus PGO 439.568 μs. Previous chain default was 1133.721 μs. Both pass precision (rtol 1e-4, atol 1e-5). Native PGO is disabled and outer TOPN=1 for default runs. The independent PGO replay uses a previous Top10 search, not a new search. Source/binary/dependency identity and complete tiling were checked. Chain local keys are 1/1/2; the actual g2 device case is 4. Default cores are 56/56/56; PGO uses 54/54/55. Matching templates do not imply identical tiling.

The chain also needs the [RA symbolic-inner-width correction](../../../../vector/reduce/design_en.md). Native candidate costs now rank the fast family ahead of the old default. [Target evidence](https://gitcode.com/zhang_shengjie/CANN-DevTools/blob/6733c737b04f2e6289ebeb5784adaccb7c1e6d30/att_generalization/report/20261119/pr3065-model-regression/dense-bulk-v1/target-results.json) and [candidate costs](https://gitcode.com/zhang_shengjie/CANN-DevTools/blob/6733c737b04f2e6289ebeb5784adaccb7c1e6d30/att_generalization/report/20261119/pr3065-model-regression/dense-bulk-v1/candidate-costs.json) retain the full fields and dispatch mapping.

All 40 inputs representing 17 cases and 36 distinct inputs representing 48 transpose cases retain complete execution identity versus e273: full tiling, workspace, block dimensions, device sources and frozen runtime dependencies. Existing device evidence is reused; no new 453-case run is claimed. Host-only 64/72-core resource replay also selects case0 and cases1/1/4. These are not 64/72-core device measurements.
