# Transpose 模型验证报告

> 本报告基于 [samples.csv](samples.csv) 的实测数据（46 条）。model_predict_cycles 来自
> [design.md](../../../design.md) 公式（`TransposePerf` 实现）在 stride_count=1、
> gather_count=2、repeat_elm=64 口径下的推导值，再乘以 outer_loop。
> 误差定义：`error = (predict - measured) / measured * 100%`，正值表示高估。

## 环境与版本

见 [manifest.json](manifest.json)。

## 预测口径

- `repeat` 列即 repeat_time（cal_count = 64 * repeat），`tail_repeat = repeat - 1`。
- `inner_stride = 1` → stride_count = 1 → inner_dim ∈ {1,2} 时 gather_count = 2，inner_dim = 3 时 gather_count = 2。
- 各分支指令成本公式（od = outer_dim，rt = repeat）：

| 分支 (total_dim, inner_dim) | 索引生成 | 搬运 | latency | 预测公式 |
| --- | --- | --- | --- | --- |
| (2,1) / (3,1) / (4,1) | GenOne = 3·rt | 3·od·rt | 69 | (3+3·od)·rt+89 |
| (3,2) / (4,2) | GenTwo = 17+17·(rt-1) | 3·od·rt | 167 | (3·od+17)·rt+187 |
| (4,3) | GenThree = 17+17·(rt-1) | 3·od·rt | 386 | (3·od+17)·rt+406 |
| (2,2)（通用分支） | GenTwo = 17+17·(rt-1) | 3·rt | 167 | 20·rt+187 |
| (3,3)（通用分支） | GenThree = 17+17·(rt-1) | 3·rt | 386 | 20·rt+406 |

- 最终预测 = 分支公式 × outer_loop（除 (4,1) 分支为 25 外，其余均为 22）。

### 关键发现

1. **整体精度良好**：46 条中 45 条误差在 ±1.5% 以内，整体 MAE 0.69%，分支 latency 常数
   （69/167/386）与 MicroAPI 吞吐表标定与实测吻合。
2. **离群点**：(3,1) cal_count=128（rt=2）预测 2222，实测 2065.46（+7.58%）。相同参数组合在
   其他分支（(2,1) +0.16%、(4,2) +0.32%）均正常。
3. **长 repeat 轻微高估**：cal_count=512（rt=8）时 (2,2)/(3,2)/(4,2) 均高估 +1.0%~+1.2%，
   搬运段 3·rt 项（kGather2/kStore 吞吐=1）在大 repeat 下略保守。
4. **(4,3) od≥2 轻微低估**：rt=1、od∈{2,4,8} 时系统性低估 -0.9%~-1.0%，GenThree 索引段
   或 latency 386 标定略偏低。

## 结论

- 除 1 个离群点外，全部用例误差在 ±1.5% 以内，模型可用于 ATT 性能评估。
- 分支结构与常数标定（head=20、69/167/386、GenTwo/GenThree 17+17·tr）整体正确。
