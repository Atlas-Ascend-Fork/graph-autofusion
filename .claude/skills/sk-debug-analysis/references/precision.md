# 精度问题分析

所需产物：`sk_meta`、`static_kernel_compile_outputs`、`plog`、`profiling`，以及用于判断精度是否正常的输出结果。

## 1. 通过开关 SK 确认问题是否由 SK 引入

保持输入和精度判定标准一致，分别检查关闭 SK 与开启 SK 时的结果：

- 关闭 SK 正常、开启 SK 异常：继续排查 SK 引入问题的阶段。
- 关闭 SK 时也异常：尚不能确认问题由 SK 引入，应先查明关闭 SK 时的精度问题。

已有可比较结果时直接使用；缺少结果时，再补充对应的对照运行。

## 2. 通过三步测试区分问题来源

在已确认开启 SK 后出现精度异常的条件下，依次进行以下测试。每项测试保持其他条件一致，分别记录配置、精度结果和对应产物。

### 2.1 图优化：排查图融合优化

开启 `debug_per_op_max_core_num`，比较精度问题是否仍然出现，判断是否与 SK 内图融合优化有关。

### 2.2 图优化：排查同步控制

开启 `debug_sync_all`，比较精度问题是否仍然出现，判断是否与 SK 内同步控制有关。

### 2.3 图编译：排查子算子 SK 编译

关闭对应子算子的 SK 编译，比较精度问题是否仍然出现，判断是否由该编译阶段引发。这里调整的是对应子算子的 SK 编译，不是关闭整个 SK。

具体选项和子算子编译开关的设置方式，以现场使用的框架与版本为准。记录每项测试的实际配置，避免将多个改动的效果混在一起。

## 3. 若指向图优化，二分最小融合范围

若上述测试指向图优化问题，二分缩小融合范围，每次比较精度结果，直至找到仍会触发精度异常的最小融合范围，再对该范围进行进一步分析。

报告中列出 SK 开关对照、三项测试的配置与结果，以及已缩小的融合范围。调试选项改变精度现象可用于缩小排查范围，具体根因仍需结合该范围内的产物和实现分析。
