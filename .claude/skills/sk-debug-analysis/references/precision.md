# 精度问题分析

所需产物：`sk_meta`、`static_kernel_compile_outputs`、`plog`、`profiling`，以及用于判断精度是否正常的输出结果。

## 1. 通过开关 SK 确认问题是否由 SK 引入

保持输入和精度判定标准一致，分别检查关闭 SK 与开启 SK 时的结果：

- 关闭 SK 正常、开启 SK 异常：继续排查 SK 引入问题的阶段。
- 关闭 SK 时也异常：尚不能确认问题由 SK 引入，应先查明关闭 SK 时的精度问题。

已有可比较结果时直接使用；缺少结果时，再补充对应的对照运行。

## 2. 通过三步测试区分问题来源

在已确认开启 SK 后出现精度异常的条件下，依次进行以下测试。每项测试保持其他条件一致，分别记录配置、精度结果和对应产物。

### 2.1 图优化：排查图融合优化

开启 `debug_per_op_max_core_num`，比较精度问题是否仍然出现，判断是否与 SK 内图融合优化有关。

1. **准备基准结果。** 确认关闭 SK 时精度正常、默认开启 SK 时精度异常。两次运行使用相同输入、shape、dtype 和精度判断标准。
2. **只增加一个选项重跑。** 在默认 SK 配置上开启 `debug_per_op_max_core_num=1`，不要同时修改其他调试选项。该选项会把可融合算子拆成逐算子 SK，仍然执行 SK，并可能自动开启 `debug_cross_core_sync_check`；它不是“只使用 1 个核”。
3. **确认实验确实生效。** 从 `super_kernel.log` 确认选项已开启；从 `sk_fused_nodes.log`、scope 日志或 task queue 确认目标算子已逐算子执行。若目标算子回退、未进入 SK 或选项未生效，本次结果不能用于判断。
4. **比较精度并决定下一步。**

   - **精度恢复正常：** 说明默认的融合、调度或同步条件参与了问题，但还不能确定具体原因。恢复默认配置，按第 3 节继续缩小异常融合范围，再单独执行第 2.2 节。
   - **精度仍然异常：** 说明问题在逐算子 SK 下仍可复现，不能只归因于多算子融合。继续查找第一个出现偏差的算子，确认其输入是否已经异常，再执行第 2.2 和 2.3 节。
   - **变成卡死、超时或执行失败：** 本次没有有效精度结论，保留现场并转入 [SK 卡死问题分析](hang.md)。

该实验只能缩小范围，不能单独确认根因。后续验证时每次只改变一个因素，并保留两次运行的输出、日志、`sk_meta` 和实际运行二进制用于对比。

### 2.2 图优化：排查同步控制

开启 `debug_sync_all`，比较精度问题是否仍然出现，判断是否与 SK 内同步控制有关。

`debug_sync_all=1` 会在子算子之间使用更强的全核同步，让相关核完成当前阶段后再继续执行。它主要改变同步方式和执行时序，区别于第 2.1 节的逐算子 SK 拆分。

1. **恢复默认 SK 配置。** 使用相同输入和精度标准，确认原精度问题仍存在。
2. **只开启 `debug_sync_all=1` 重跑。**
3. **比较精度并决定下一步。**

   - **精度恢复正常：** 优先怀疑默认同步关系或执行时序。按第 3 节缩小异常融合范围，对比开关前后的同步点、依赖关系和参与核，检查后续算子是否过早读取前序结果。
   - **精度仍然异常：** 加强同步未消除问题，继续第 2.3 节检查子算子 SK 编译；不能仅凭这个结果排除全部同步问题。
   - **变成卡死、超时或执行失败：** 本次没有有效精度结论，保留现场并按 [SK 卡死问题分析](hang.md) 或具体错误类型定位。

精度恢复只能说明问题对同步或时序变化敏感，不能直接确认缺少某处同步。应针对最小异常范围做单因素验证；该选项可能降低性能，不将调试运行用于性能评价。

### 2.3 图编译：排查子算子 SK 编译

关闭对应子算子的 SK 编译，比较精度问题是否仍然出现，判断是否由该编译阶段引发。

关闭某个算子对应的 sk 编译的方法：调用op_compiler工具，直接只编译某个对应的算子，对其不启用sk编译，然后覆盖安装。运行时验证的方法：通过`realelf -sW xxx.o | grep GLOBAL`来看符号表，没有sk相关入口就是成功的。

## 3. 若指向图优化，二分最小融合范围

若上述测试指向图优化问题，二分缩小融合范围，每次比较精度结果，直至找到仍会触发精度异常的最小融合范围，再对该范围进行进一步分析。

报告中列出 SK 开关对照、三项测试的配置与结果，以及已缩小的融合范围。调试选项改变精度现象可用于缩小排查范围，具体根因仍需结合该范围内的产物和实现分析。
