# 采集、拟合与修复验证

根据任务范围使用对应章节。已有离线数据缺少某项记录时，列明适用边界，按已授权范围补采。

## 采样与缓存口径

每个 run 记录输入、设备与频率信息、实际加载库及内容标识、运行顺序、warmup、采样次数、
计时指标和统计方法。逐次 profile 应能关联到调用、shape 和最终 tiling 身份；
相同算子名下的多次调用不能仅按名称合并。多算子时延之和与端到端时延分别报告。

采集前确定需要衡量原框架缓存行为还是冷数据搬运，并记录对应条件：

- 原框架测量保留实际调用方式，说明输入是否复用及缓存 hint，结论限定在该运行条件下。
- 冷数据搬运测量记录每次搬运的 GM offset、核与 repeat 间的地址分配、工作集规模、
  缓存容量及地址轮换周期，检查测试区间内是否重复访问相同数据。
  使用目标 API 支持的 L2 hint（如 `SetL2CacheHint(CACHE_MODE_DISABLE)`），
  并在可采集时核对 L2 hit/miss 等计数。设置 hint 本身不能证明所有访问均绕过 L2。

微基准与端到端运行分别标注缓存条件。冷数据拟合通过不能替代端到端缓存条件的核验。
比较基线和候选时采用相同采集协议；交替或反序复测可用于检查运行顺序影响。
对超出容限或接近阈值的变化，结合样本分布和重复测量判断，避免把单次波动归因于模板切换。

## 模型重拟合

先核对实际 API 参数、循环和尾块，再决定拟合项。记录参数含义、单位、适用硬件/API/dtype、
shape/stride 范围和缓存条件，说明哪些参数改变、哪些保持原值及其依据。

拟合数据与验证数据分开，保留样本选择、残差分布及参数不确定性。
验证数据覆盖目标场景内不同的数据量、stride、repeat 和尾块；覆盖不足时限定模型适用范围。
已确认原因为执行次数或参数映射错误时，先修正相应逻辑，避免用拟合系数吸收错误。
微基准误差降低后，还需检查候选排序和重新求解后的默认运行性能。

## 成对回归

按用户要求和变更影响选择用例，不固定用例数量。覆盖目标问题、潜在退化场景及相关输入类别，
保存确定的用例清单和选择依据。用例无法执行时记录原因；替换后重新核对覆盖范围。

逐用例保留基线与候选的运行记录、profile 路径、计时值、变化率、样本数量和库内容标识。
变化率统一为 `(候选时延 / 基线时延 - 1) × 100%`，正值表示变慢。
报告有效配对数、缺失数、中位数、几何平均时延比及超出约定容限的用例，保留逐例表。
几何平均只使用有效正时延配对，说明排除的数据及原因。

对显著改善、显著退化和已发现模板变化的用例，核对两侧完整最终身份及选择原因；
需要统计总体模板切换数量时，采集整个统计范围的身份。
分别记录身份可比较数、已确认切换数和未知数。未解析身份不能记为没有切换，
少数锚点的核对结果不能推广到其余用例。

分别保留以下结果，按测试框架真实字段解释状态：

| 结果 | 记录内容 |
| --- | --- |
| 执行 | 命令退出码、超时或崩溃信息 |
| profiling | 数据是否完整、计时口径是否可比 |
| 精度 | 明确的数值比对或判定证据；缺失标为未知 |
| 性能 | 基线与候选变化、抖动和是否超出约定容限 |
| 定位 | 最终身份、排序归因及尚未验证的解释 |

沿用项目或任务已有的验收容限；未约定时说明用于筛查的阈值及依据。
总体收益不能抵消尚未解释的显著退化。报告列明退化及证据，待复测或修复后再判断是否达到验收要求。
